# Безопасность

## Реальные звонки заблокированы по умолчанию

Реальный звонок возможен только при выполнении **всех** условий сразу (`src/wewln_phonecaller/safety.py`):

1. `WEWLN_MODE=production`;
2. `WEWLN_PRODUCTION_CONFIRM=I_ACCEPT_REAL_CALLS`;
3. kill switch выключен (`WEWLN_KILL_SWITCH=false`);
4. выбранный провайдер телефонии умеет звонить на реальные номера;
5. оператор явно «взвёл» систему (команда `arm` с ограниченным сроком появится в фазе 6).

В этой версии есть только провайдер `mock`, а `arm` ещё не реализован, поэтому реальные звонки
невозможны при любых настройках. Текущее состояние видно в `check-config` (`real_calls_allowed`)
и в `/ready` (`checks.real_calls`). `wewln simulate` и синхронизация с Notion телефонию не
используют вообще: задания только отмечаются как выполненные в режиме симуляции.

## Секреты

- Секреты хранятся только в переменных окружения, в `.env` (исключён из git) или — для токена
  Notion — в Диспетчере учётных данных Windows (`wewln notion token set`, рекомендуется).
  Токен вводится без отображения на экране и не попадает в историю команд.
- В коде токены — `SecretStr`. В выводе CLI, в ответах API и в логах вместо них стоит `set` или `***`.
  Значения секретов передаются маскировщику логов при запуске.
- Если токен Notion мог утечь, обновите его на вкладке **Configuration** подключения в портале
  разработчика Notion и сохраните новый; `wewln notion token delete` удаляет сохранённый.
- Сообщения об ошибках настроек называют переменную, но не показывают её значение.
- Сравнение токена API — за постоянное время (`hmac.compare_digest`).

## Сеть

- HTTP API по умолчанию слушает только `127.0.0.1`.
- Если указать адрес не из loopback без `WEWLN_API_TOKEN`, программа откажется запускаться.
- Всё, кроме `/health` и `/ready`, требует Bearer-токен. Без настроенного токена эти эндпоинты
  закрыты (fail closed).
- Ответы об ошибках не раскрывают внутренние детали; подробности есть только в логе, по `request_id`.
- Исходящие запросы — только к Notion API по HTTPS с проверкой сертификата. Обычный `http://`
  разрешён лишь для локальной имитации на `127.0.0.1`/`localhost`.

## Доступ к Notion

- Подключению нужны только возможности Read, Update и Insert content; сведения о пользователях
  не нужны.
- Дайте подключению доступ только к странице с базами wewln: подключение видит лишь то, чем
  с ним поделились.
- wewln не удаляет страницы и базы и не меняет типы свойств. Он создаёт базы, недостающие
  свойства и варианты select, страницы заданий и результатов; обновляет свойства заданий,
  «Сводку» и «Ошибку» кампаний и контактов, а также «Статус» остановленной в wewln кампании
  и флажок «Не звонить» у контактов из локального списка.

## Персональные данные

- Номера телефонов маскируются в логах и в журнале аудита до записи на диск: остаются только
  первые две и последние две цифры (`+79*******67`). Команды `contacts list`, `jobs list`
  и `dnc list` тоже показывают маскированные номера (полные — только с `--unmask`).
- Синхронизация с Notion пишет в лог и в историю циклов только счётчики, коды ошибок и ID,
  без имён, номеров и текста страниц. Сообщения об ошибках Notion сокращаются и маскируются.
- Имена и номера контактов хранятся полностью в SQLite (`data\wewln.db`): номер нужен для
  звонка. Папка `data\` должна быть доступна только вам (профиль пользователя Windows).
  Те же данные лежат в вашем рабочем пространстве Notion, если вы его подключили.
- Удаление данных: пока только вручную (удалить `data\wewln.db`); команда `purge` со сроками
  хранения появится в фазе 6.
- Записи разговоров, транскрипты и срок их хранения появятся в фазах 5–6. Запись будет
  выключена по умолчанию.

## Чего в проекте не будет

Функций для подмены номера (caller ID spoofing), обхода антиспам-систем, согласия абонентов
или ограничений провайдеров.

## Как сообщить о проблеме

Не публикуйте сведения об уязвимости в открытом issue. Сообщите владельцу репозитория напрямую
(например, через **Security → Report a vulnerability** на GitHub, если эта функция включена)
и не прикладывайте реальные токены или номера.
