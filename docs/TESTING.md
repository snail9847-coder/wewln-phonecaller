# Тестирование

## Локальный запуск

Windows (PowerShell):

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
```

Linux: те же команды через `.venv/bin/python`.

Тестам не нужны интернет, аккаунт Notion, телефония и модели ИИ (кроме `-m voice_models`). Notion заменён имитацией
API (`notion/mock_server.py`) на `127.0.0.1`, Asterisk — имитацией ARI (`tests/ari_simulator.py`):
HTTP и WebSocket, события звонков, ошибки и обрывы связи. Тесты с настоящим Asterisk
(`tests/test_asterisk_live.py`) и с настоящими моделями (`tests/test_voice_models.py`) без них
пропускаются: `481 passed, 16 skipped`. Каждый тест работает во временной папке,
переменные `WEWLN_*` с компьютера в тесты не попадают, настоящее хранилище учётных данных
Windows не используется (его заменяет хранилище в памяти).

## CI

`.github/workflows/ci.yml` запускается при push в `main`, на каждый pull request и вручную.

- **`test`**: `ubuntu-latest` и `windows-latest` × Python 3.12, 3.13 и 3.14. Шаги: установка,
  `ruff check`, `ruff format --check`, `pytest`, `check-config`.
- **`asterisk-live`**: `ubuntu-24.04` (Asterisk 20 LTS) и `ubuntu-26.04` (Asterisk 22 LTS) из
  пакетов Ubuntu. `deploy/asterisk/ci/setup.sh` ставит Asterisk, копирует примеры конфигурации
  из `deploy/asterisk/` и добавляет тестовый диалплан `deploy/asterisk/ci/extensions-ci.conf`.
  Затем `pytest -m asterisk_live` и `wewln telephony check`. Звонки идут на Local-каналы этого
  диалплана: без SIP-аккаунта и телефонной сети, ничего не покидает машину CI. Пароль ARI
  случайный для каждого запуска и скрыт в логе. Итог тестов и версия Asterisk видны в аннотациях
  на странице запуска, при ошибке — ещё и её подробности (`.github/scripts/annotate.py`).
  Голосовые тесты здесь: Asterisk подключается к AudioSocket-серверу wewln, проигрывает запись
  в звонок (`994124980150`) или возвращает эхо (`994124980151`); модели поддельные.
- **`voice-models`**: `ubuntu-latest` и `windows-latest`, Python 3.12, `pip install -e ".[dev,voice]"`.
  `wewln voice download all` скачивает модели Vosk и Piper (около 110 МБ, размер и SHA-256
  проверяются; кэш между запусками), затем `wewln voice check --no-llm` и
  `pytest -m voice_models`. Диалоговая модель поддельная: Ollama в CI не ставится.

## Тесты с настоящим Asterisk на своём ПК

Нужен Asterisk, настроенный по [ASTERISK.md](ASTERISK.md) (шаги 1–4). Добавьте тестовый
диалплан в Ubuntu (путь — ваша папка с wewln):

```bash
cd /mnt/c/Users/ИМЯ/wewln-phonecaller
sudo tee -a /etc/asterisk/extensions.conf < deploy/asterisk/ci/extensions-ci.conf > /dev/null
sudo asterisk -rx "dialplan reload"
```

Затем в PowerShell в папке wewln:

```powershell
$env:ASTERISK_LIVE_ARI_URL = "http://127.0.0.1:8088"
$env:ASTERISK_LIVE_ARI_USER = "wewln"
$secret = Read-Host "ARI password" -AsSecureString
$env:ASTERISK_LIVE_ARI_PASSWORD = [Net.NetworkCredential]::new("", $secret).Password
.venv\Scripts\python.exe -m pytest -q -m asterisk_live
```

Тесты звонят только на расширения `[wewln-ci]` через Local-каналы, SIP-транк не используется.
Для голосовых тестов Asterisk в WSL2 должен достучаться до wewln в Windows: при сети NAT
задайте адрес адаптера WSL — `$env:ASTERISK_LIVE_AUDIOSOCKET_HOST = "172.28.144.1"` (ваш адрес
из [ASTERISK.md](ASTERISK.md), шаг 6а).
После проверки уберите блок `[wewln-ci]` из `/etc/asterisk/extensions.conf` и выполните
`sudo asterisk -rx "dialplan reload"`.

## Тесты с настоящими моделями на своём ПК

Нужны пакеты голоса и модели ([VOICE.md](VOICE.md), установка — только с вашего согласия):

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev,voice]"
.venv\Scripts\wewln.exe voice download all
$env:WEWLN_TEST_MODELS_DIR = "$PWD\data\models"
.venv\Scripts\python.exe -m pytest -q -s -m voice_models
```

Без моделей эти тесты пропускаются. Ollama они не используют; её проверяет `wewln voice check`.

## Что тесты не покрывают

- Ручную проверку на ПК владельца с Windows 10/11. CI на `windows-latest` — это Windows Server,
  а не домашняя Windows 10/11. Чек-лист ручной проверки появится в фазе 7.
- Остановку по `Ctrl+C` в Windows. В CI процесс на Windows завершается принудительно
  (`TerminateProcess`), поэтому штатная остановка и запись `app.stop` проверяются только на Linux.
- Настоящий Notion. Код проверен только на имитации API; поведение настоящего API может
  отличаться в деталях. Первое подключение — по шагам из [NOTION.md](NOTION.md), затем
  `wewln notion check` и `wewln notion sync`.
- Настоящий Диспетчер учётных данных Windows: тесты используют хранилище в памяти и поддельный
  модуль `keyring`. Проверка на ПК: `wewln notion token set`, затем `wewln notion token status`.
- Звонки через SIP-транк в телефонную сеть +7 и +994. Настоящий Asterisk проверен в CI только
  с Local-каналами; регистрация у провайдера, SIP, звук и реальные причины завершения от
  провайдера не проверялись. Для этого нужен аккаунт у провайдера и отдельное разрешение
  владельца на один тестовый звонок ([ASTERISK.md](ASTERISK.md), шаг 8).
- Софтфон MicroSIP и сеть WSL2 на домашней Windows 10/11 (шаги 1 и 6 в [ASTERISK.md](ASTERISK.md)).
- Голосовой разговор на ПК владельца: скорость моделей на его процессоре, Ollama с
  `qwen3:4b` (в песочнице проверялась только `qwen3:0.6b`), сеть между Asterisk в WSL2 и
  wewln в Windows, звук и эхо софтфона MicroSIP. Проверка — по трём уровням из
  [VOICE.md](VOICE.md).
- Качество разговора и распознавания живой речи по телефону: в тестах «собеседник» говорит
  синтезированным голосом Piper.

## Ручная проверка с настоящим Notion

Только на своём рабочем пространстве и с тестовыми данными (без реальных номеров клиентов):

1. Шаги 1–7 из [NOTION.md](NOTION.md): `wewln notion check` заканчивается строкой
   `Notion is ready for the sync.`
2. Кампания «Тест» со статусом «Запущена» и два контакта, один с флажком «Не звонить».
   `wewln notion sync` → в «Задания на звонки (wewln)» два задания: «В очереди»
   и «Заблокировано».
3. Повторный `wewln notion sync` не создаёт новых страниц.
4. `wewln simulate`, затем `wewln notion sync` → задание «Выполнено», в «Результаты звонков
   (wewln)» одна страница, «Сводка» кампании обновлена.
5. `wewln campaign stop <id>` → после `wewln notion sync` у кампании в Notion статус
   «Остановлена»; если вернуть «Запущена», следующая синхронизация вернёт «Остановлена».
6. В логе `data\logs\wewln.log` нет токена, имён и номеров телефонов.
