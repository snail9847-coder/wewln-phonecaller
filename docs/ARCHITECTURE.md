# Архитектура

## Сейчас: фаза 5 (голосовой движок)

```text
cli.py ── check-config · init-db · serve · notion … · campaign … · contacts … · jobs · dnc …
  │       · telephony … · calls … · simulate; cli_voice.py — voice … · calls preflight · transcript
  ├─ config.py ─────── Settings: WEWLN_* и .env, проверка, SecretStr; секреты из secret_store.py
  ├─ logging_setup.py ─ JSON или текст, request_id и call_id, маскировка (redact.py)
  ├─ domain.py ─────── статусы кампаний и заданий, причины, исходы, русские подписи для Notion
  ├─ phones.py ─────── номера → E.164 (phonenumbers), страна и тип номера, политика набора
  ├─ storage/ ──────── SQLite: WAL, миграции, audit_log, блокировки;
  │                    repository.py — кампании, контакты, «Не звонить», задания, результаты;
  │                    calls.py — попытки, события провайдера, разрешения, аварийная остановка
  ├─ notion/ ───────── client.py (REST, лимит скорости, ретраи), schema.py, props.py, ids.py,
  │                    setup.py (bootstrap и проверка баз), sync.py (цикл и фоновый сервис),
  │                    mock_server.py (имитация Notion API для тестов и пробы)
  ├─ safety.py ─────── гейт реальных звонков
  ├─ telephony/ ────── base.py (интерфейс провайдера), mock.py, asterisk.py (ARI),
  │                    lifecycle.py (статусы и итоги), service.py (сервис звонков),
  │                    webhooks.py (подписанные события), factory.py
  ├─ voice/ ────────── audio.py, vad.py (детектор речи), transport.py (AudioSocket, линия в памяти),
  │                    stt.py · llm.py · tts.py (движки), text.py (предложения, метки, отказ),
  │                    engine.py (разговор), runtime.py (сборка по настройкам), simulate.py
  └─ api/app.py ────── aiohttp: /health, /ready, /api/v1/… (info, notion, campaigns, dnc, calls,
                       telephony/events); middleware: request_id → JSON-ошибки → токен → обработчик
```

| Модуль | Ответственность |
| --- | --- |
| `config.py` | Загрузка и проверка настроек (pydantic-settings). Перекрёстные проверки: `production` только с фразой подтверждения, адрес не из loopback — только с токеном, Notion — только с токеном и четырьмя ID баз. Ошибки называют переменные, но не показывают значения |
| `secret_store.py` | Токен Notion, пароль ARI и ключ вебхуков в хранилище ОС через `keyring` (в Windows — Диспетчер учётных данных). Хранилище подменяется в тестах; без `keyring` — понятная ошибка и подсказка про переменную окружения |
| `errors.py` | Иерархия ошибок со стабильными кодами и HTTP-статусами: `config_invalid`, `storage_error` (503), `unauthorized` (401), `real_calls_blocked` (409) и др. |
| `redact.py` | Маскировка номеров (первые и последние две цифры) и секретов. Даты и время не принимаются за номера |
| `logging_setup.py` | Форматтеры JSON и текста, контекст `request_id` и `call_id` через `contextvars`, маскировка всего, что попадает в лог, файл с ротацией в UTF-8. Разовые команды пишут лог только в файл |
| `domain.py` | Коды статусов (хранятся в SQLite и не меняются) и русские подписи (видны в Notion) |
| `phones.py` | Разбор номера, E.164, причины отказа: не указан, не распознан, нет кода страны. Политика набора: только страны из `WEWLN_CALL_REGIONS`, никогда — платные службы. Это проверка формата, а не доступности номера |
| `storage/db.py` | Короткие подключения к SQLite, режим WAL, транзакции `BEGIN IMMEDIATE`, миграции «только вперёд», проверка готовности без создания файла, журнал аудита, блокировки с истечением срока (lease) |
| `storage/repository.py` | Единые правила для локального режима и Notion: окончательная остановка, приоритет «Не звонить», одно задание на пару «кампания + контакт», планирование заданий, симуляция |
| `storage/calls.py` | `CallStore`: попытка записывается до набора и перед ним заново проверяет все условия; события применяются один раз по ключу; итог попытки и статус задания — в одной транзакции; разрешения на реальный звонок; аварийная остановка для всех процессов |
| `notion/client.py` | REST-клиент на aiohttp: `Notion-Version: 2026-03-11`, не больше `WEWLN_NOTION_MAX_RPS` запросов в секунду, ретраи чтения на 429/5xx/таймауты с `Retry-After` и бэкоффом; создание страниц не повторяется вслепую; постраничное чтение и деление выборки по времени создания из-за предела в 10 000 результатов; токен не попадает в сообщения |
| `notion/schema.py`, `props.py`, `ids.py` | Схема четырёх баз, сравнение с фактической, тело «починки»; чтение и запись значений свойств; ID и ссылки Notion |
| `notion/setup.py` | `bootstrap` (создать или найти базы под страницей, без дублей) и `resolve_workspace` (найти настроенные базы, сверить схему, при `--repair` добавить недостающее) |
| `notion/sync.py` | `NotionSync.run_once()` — один цикл синхронизации; `SyncService` — фоновые циклы в `serve` с интервалом, бэкоффом и пробуждением после остановки или «Не звонить» |
| `notion/mock_server.py` | Имитация используемых эндпоинтов Notion API со сбоями по заказу: 401, 403, 404, 409, 429, 5xx, записи «сохранено, но ответ 5xx», предел 10 000 результатов, 25 связей на странице |
| `safety.py` | `evaluate_real_calls()` возвращает решение и **все** причины блокировки |
| `telephony/base.py` | Интерфейс провайдера: `start`, `place_call`, `hangup`, `call_exists`, `check`, `close`; события `ProviderEvent` (dialing, ringing, answered, hangup с причинами Q.850 и SIP). ID звонка у провайдера выводится из ключа попытки. Реестр `PROVIDERS`: флаг `places_real_calls` у `mock` — `False`, у `asterisk` — `True` |
| `telephony/mock.py` | Симуляция со сценариями (`WEWLN_MOCK_SCENARIO`): ответ, занято, нет ответа, отказ, недоступен, ошибка, тишина, долгий разговор или смесь по последней цифре номера |
| `telephony/asterisk.py` | Asterisk через ARI: `POST /ari/channels/{id}` с ID из ключа попытки (запрос не повторяется; тот же ID, пока канал жив, → 409), события по WebSocket с переподключением, причины из `ChannelDestroyed` и `Dial`, сообщение после ответа, завершение чужих каналов. Пароль — только в заголовке `Authorization` |
| `telephony/lifecycle.py` | Статусы звонка и переходы только вперёд; итог по причине завершения; что будет с заданием: выполнено, повтор, отказ или отмена |
| `telephony/service.py` | `CallService`: один дозвонщик (блокировка в SQLite), набор по одному, таймаут звонка и лимит длительности, отмена и аварийная остановка, восстановление после сбоя, тестовые звонки |
| `telephony/webhooks.py` | Проверка подписи HMAC-SHA256, времени и формата событий `POST /api/v1/telephony/events` |
| `api/app.py` | HTTP API, `X-Request-ID`, единый JSON-формат ошибок, Bearer-токен, проверки готовности; запуск и остановка фоновой синхронизации вместе с сервером; список звонков, отмена, аварийная остановка, вебхуки |
| `voice/engine.py` | `ConversationSession`: приветствие, приём реплик (детектор речи, конец по паузе), распознавание, ответ LLM потоком, озвучка по предложениям через `Player` (в реальном времени, с остановкой при перебивании), защита от эха, переспрашивание, лимиты, итог `SessionResult` и реплики `Turn` |
| `voice/vad.py` | Энергетический детектор речи по кадрам 20 мс: порог над шумом линии (минимум за 1,5 с), начало и конец реплики, отсев щелчков, обрезка монолога, «пол» для эха |
| `voice/transport.py` | `MediaStream`; AudioSocket-сервер (TCP, slin 8 кГц): только локальные и частные адреса, только ожидаемый UUID звонка; линия в памяти для `mock` и тестов |
| `voice/stt.py`, `llm.py`, `tts.py` | Vosk, faster-whisper, сервер whisper.cpp; Ollama (поток, прогрев, без режима размышлений), сервер с API OpenAI; Piper, HTTP-сервер Piper. Пакеты моделей загружаются только при использовании |
| `voice/runtime.py` | `VoiceRuntime`: движки по настройкам, загрузка и прогрев при старте дозвонщика, заранее синтезированные фразы, новая сессия на каждый ответивший звонок |
| `cli_voice.py` | `voice check`, `voice chat`, `voice simulate`, `voice download` (закреплённые адреса, размер и SHA-256), `calls preflight`, `calls transcript` |
| `cli.py` | Команды и коды выхода (0 — ок, 1 — ошибка выполнения, 2 — ошибка настроек), UTF-8 в консоли Windows, импорт CSV (UTF-8 или Windows-1251; `,`, `;` или табуляция) |

### Запуск `serve`

1. Загрузка и проверка настроек. Если они неверны — выход с кодом 2, сервер не стартует.
2. Настройка логов. Значения секретов заранее передаются маскировщику.
3. Миграции БД. Ошибка — выход с кодом 1.
4. Запись `app.start` в журнал аудита вместе с решением гейта реальных звонков.
5. Запуск aiohttp на `WEWLN_HTTP_HOST:WEWLN_HTTP_PORT`. Если `WEWLN_NOTION_ENABLED=true`,
   вместе с ним стартует фоновая синхронизация: первый цикл сразу, дальше раз в
   `WEWLN_NOTION_SYNC_INTERVAL` секунд. Сбой Notion не останавливает сервер. При штатной
   остановке — запись `app.stop`.

`serve` номера не набирает: звонит отдельный процесс `wewln calls run` или `wewln calls test`.
Отмена и аварийная остановка через API записываются в SQLite, и звонящий процесс выполняет их
примерно за полсекунды.

### Цикл синхронизации с Notion

1. Взять блокировку `notion_sync` в SQLite (одна синхронизация на базу данных, срок 5 минут,
   продлевается во время работы).
2. Найти четыре базы и сверить схему. Отсутствующее свойство, неверный тип или связь не с той
   базой останавливают цикл с подсказкой `wewln notion check --repair`.
3. Прочитать все кампании и контакты (полный просмотр, связи больше 25 — дочитываются).
   Удалённые страницы определяются только по полному списку.
4. Спланировать задания в SQLite: «Не звонить», ошибки номера, остановка и пауза.
5. Записать в Notion: статус остановленных в wewln кампаний, флажок «Не звонить» по локальному
   списку, ошибки номеров у контактов, страницы заданий (по ключу идемпотентности), результаты
   и «Сводку» кампаний.
6. Сохранить итог цикла в `notion_sync_runs`; в лог — только счётчики и коды ошибок.

Правила, кто что меняет и как устроена защита от дублей, — в [NOTION.md](NOTION.md).

### Звонок

```text
pending ──▶ dialing ──▶ ringing ──▶ answered ──▶ completed
   └───────────┴───────────┴──▶ busy · no_answer · rejected · unreachable · failed · cancelled
```

1. `CallStore.begin_*` в одной транзакции проверяет всё заново (аварийная остановка, статус
   кампании, «Не звонить», состав кампании, попытки, политика номера, для реального звонка —
   разрешение) и записывает попытку `pending`. Прямо перед запросом к провайдеру
   (`CallService._dial_blocker`) всё проверяется ещё раз: аварийная остановка, отмена,
   задание, кампания, контакт, «Не звонить», для реального номера — гейт реальных звонков,
   регионы, политика номера и разрешение. Если что-то изменилось, номер не набирается.
2. ID звонка у провайдера выводится из ключа попытки. Запрос на набор отправляется один раз и
   не повторяется. Если ответ не дошёл (тайм-аут, обрыв, 5xx без ответа на вопрос, есть ли
   канал), попытка становится `dialing` с ошибкой `provider_uncertain`: сервис ждёт событий и
   кладёт трубку по таймерам. Ctrl+C во время запроса не обрывает его: сервис ждёт ответа до
   12 секунд, а затем кладёт трубку.
3. События провайдера (ARI по WebSocket, вебхуки, `mock`) сохраняются в `call_events` один раз
   по ключу и двигают статус только вперёд.
4. Сервис сам кладёт трубку: без ответа за `WEWLN_CALL_RING_TIMEOUT`, по истечении
   `WEWLN_CALL_MAX_DURATION`, при отмене, аварийной остановке, остановке кампании, «Не звонить»
   и удалении контакта. Пока запрос на набор выполняется, причина только записывается, а трубка
   кладётся сразу после ответа провайдера. Если провайдер не подтвердил завершение, попытка
   закрывается с причиной `hangup_unconfirmed`. Если провайдер потом сообщает о ходе такого
   звонка (событие `after_end`), трубка кладётся сразу; на любой неожиданной ошибке — тоже.
5. По итогу (`lifecycle.decide_job`) задание выполнено, ждёт повтора (`next_attempt_at`,
   после «занято» и «нет ответа», пока есть попытки) или закрыто с причиной. Результат
   попадает в `call_results` и при синхронизации — в Notion.
6. Голосовой режим (`WEWLN_VOICE_MODE=ai`): после ответа `CallService` просит у провайдера
   звук звонка (`open_media`). Asterisk создаёт мост `mixing`, канал `externalMedia` подключается
   к AudioSocket-серверу wewln с UUID звонка, оба канала попадают в мост. На звуке запускается
   `ConversationSession`; реплики сохраняются в `call_turns` по мере разговора. Конец разговора
   (прощание, просьба не звонить, тишина, лимиты, сбой моделей) кладёт трубку; аварийная
   остановка и лимит длительности действуют как обычно. С `mock` звук идёт по линии в памяти,
   собеседника играет `voice/simulate.py`.
7. После сбоя сервис сначала разбирается с попытками, которые могли остаться живыми, и только
   потом набирает новые номера. Звонок, который ещё есть у провайдера или о котором провайдер
   ничего не может сказать, завершается (`state_lost`); разговор не продолжается, номер не
   набирается повторно.

### Данные (схема версии 4)

- `schema_migrations`, `audit_log` — как в версии 1; `subject` и `details` аудита
  записываются уже замаскированными.
- `campaigns` — локальные и из Notion (`source`), статус, сценарий, язык, причина остановки,
  проблема для показа в Notion.
- `contacts` — имя, номер как введён и в E.164 (номер хранится полностью: он нужен для
  звонка), флажок «Не звонить» из Notion; `campaign_contacts` — состав кампаний.
- `suppression` — список «Не звонить» с источником: `manual`, `notion`, `opt_out`.
- `call_jobs` — задания: одно на пару «кампания + контакт», уникальный ключ идемпотентности,
  статус, причина, попытки, связь со страницей Notion и признаки неподтверждённой записи.
- `call_results` — результаты попыток с собственным ключом идемпотентности.
- `notion_sync_runs` — история циклов синхронизации; `locks` — блокировки с истечением срока.
- Версия 3: `call_attempts` — попытки звонков (вид `job` или `test`, ID у провайдера, статус,
  причины завершения, время этапов, только маскированный номер; не больше одной живой попытки
  на задание — уникальный индекс); `call_events` — события провайдера, каждое один раз;
  `real_call_permits` — разрешения на тестовый звонок на один номер; `runtime_flags` —
  аварийная остановка для всех процессов; `call_jobs.next_attempt_at` — время следующей
  попытки.
- Версия 4: `call_turns` — реплики разговора (кто, вид, текст, прерывание, время от начала,
  задержки распознавания, LLM и синтеза), удаляются через `WEWLN_VOICE_TRANSCRIPT_DAYS`;
  `call_attempts.voice_end`, `opt_out`, `voice_turns` — итог разговора.

Применённую миграцию не меняют — добавляют новую в `storage/migrations.py`.
`/ready` сообщает `schema_out_of_date`, если версия БД отстаёт от кода.

## Целевая архитектура (фаза 6 и дальше)

```text
Notion (пульт, необязателен) ─┐      локальный источник (CLI, файлы) ─┐
  контакты, сценарии, кампании,│ notion/sync.py                        │
  старт и стоп, статусы, итоги ▼                                       ▼
                     storage/repository.py: единые правила кампаний, контактов и заданий
                                  │
                     orchestrator/ ── safety/ (режим, kill switch, arm, согласие, DNC, часы, лимиты)
                                  │
                     telephony/ ── mock │ Asterisk через ARI (WSL2) │ другие адаптеры
                                  │ аудио и события звонка
                     voice/ ── STT ⇄ LLM ⇄ TTS (локально, русский язык), сценарий, история, итог
                                  │
                     storage/ ── SQLite: кампании, контакты, сценарии, звонки, реплики, итоги, аудит
```

- **Notion не обязателен.** Кампании приходят из Notion (синхронизация) или создаются
  локально (CLI); правила для обоих источников одни — в `storage/repository.py`. Состояние
  звонков всегда хранится в SQLite, а Notion получает его копию.
- **Языки.** Реестр `SUPPORTED_LANGUAGES` в `config.py`. Для каждого языка позже задаются модель
  распознавания, голос синтеза, системные подсказки LLM и фразы отказа («не звоните мне»).
- **Телефония.** Новый провайдер реализует интерфейс из `telephony/base.py` и регистрируется
  в `PROVIDERS`. Флаг `places_real_calls=True` сам по себе ничего не разрешает — нужен ещё весь
  гейт из `safety.py`. Звук разговора идёт из Asterisk в голосовой движок отдельно от
  управления звонком (AudioSocket, фаза 5).
- **Голос** (фаза 5, [VOICE.md](VOICE.md)). Впереди: версия сценария у каждого звонка и итог
  разговора по схеме (фаза 6), другие языки.

## Особенности Windows

- Пути — только через `pathlib`. Все файлы читаются и пишутся в UTF-8; вывод в консоль
  переключается на UTF-8, чтобы русский текст не ломался.
- База часовых поясов в Windows берётся из пакета `tzdata`.
- Логи закрываются явно: Windows не даёт удалить открытый файл.
- Нет зависимостей от macOS и POSIX-сигналов. Asterisk под Windows не работает нативно —
  он запускается в WSL2 ([ASTERISK.md](ASTERISK.md)); wewln остаётся программой Windows и
  обращается к ARI по `127.0.0.1`.
